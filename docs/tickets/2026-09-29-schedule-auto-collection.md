# AK-SCHEDULE-002 · NAS 신규 대회일정 자동 반영

2026-09-30 최종 사용자 지시: **공지사항처럼 새 대회가 올라오면 승인 없이 자동 반영**한다. 이전 검수 전용 일정 수집기는 교체한다. 이 결정이 기존 티켓의 승인·수집 보류 조건보다 우선한다.

주 기능은 NAS에서 어질리티 대회 게시글과 포스터를 수집해 대회일정을 만드는 것이다. 등록된 장소를 먼저 연결하고, 새 대회장일 때만 주소·GPS를 보완한다. 별도 웹은 후속 일정 조회·수정 도구이며 자동 운영의 필수 단계가 아니다.

## 처리 흐름

`NAS 예약 실행 → agility.co.kr/17 신규 어질리티 대회 감지 → 포스터 판독 → 기존 장소 연결(필요 시 신규 장소) → 전체 데이터 검증 → match.json·manifest 커밋/푸시`

- `match.json.url`의 실제 상세 idx로 이미 등록된 대회를 판별한다. 초기 실행에서 기존 일정을 재등록하지 않는다.
- 대회명·일시·접수기간·주최·종류·종목·심사위원·장소·상세 설명 등 13개 core 필드를 생성한다.
- 중복 의심과 필수 필드 오류는 해당 항목만 제외하고 초안·근거를 NAS에 남긴다.
- 검증된 신규 장소는 연결된 일정과 같은 커밋에 반영한다. 주소·좌표 미확정 항목은 임의 좌표로 등록하지 않는다.
- 원문이 바뀐 기존 일정은 결과에 남기며 수동으로 입력한 값을 자동 덮어쓰지 않는다.
- Drive는 선택 사항이다. 미설정이면 `detailImages`를 생략하고 실제 원문 링크로 확인한다.
- 반영 성공, 실패, 원문 근거는 NAS 외부 상태 디렉터리의 배치·캐시로 추적한다.

## 저장소 역할

| 저장소 | 역할 |
| --- | --- |
| agility-scraper | NAS 수집·판독·검증·자동 커밋/푸시 |
| daltiapp.github.io | 서비스 정적 JSON·데이터 계약 문서 |
| data-studio | 후속 일정 확인·수정 웹. 기존 수집 버튼/API로 중복 수집하지 않음 |

새 진입점은 `schedule_auto_real`이다. 이전 `schedule_collect_*`/`schedule_kau_*`는 차단하고 큐·공용 파서는 보존한다. 운영 설정·검증·복구 절차는 스크래퍼의 `SCHEDULE_AUTO.md`를 따른다.

## 배포 규칙

상태·캐시·배치는 데이터 저장소 밖에 둔다. manifest를 먼저 읽어 활성 JSON 경로를 결정한다. 버전 폴더와 schemaVersion은 바꾸지 않는다. 반영 직전 원격 동기화·기준 SHA·`--scope all`을 다시 확인한다. 데이터가 같으면 커밋하지 않는다.

이 수집기는 FCM을 보내지 않는다. 공지 자동 수집과 확정 일정 알림은 계속 운영한다. **1회 앱 푸시 대상이 3건 이상일 때 발송 금지** 규칙은 그대로 유지한다. JSON 자동 등록 건수와 앱 푸시 건수는 별도다.

## 검증 및 실제 운영 상태

자동 반영·중복 방지·개별 오류 격리·Git 경쟁·기존 공지 회귀 테스트와 전체 데이터 하네스를 실행한다. 로컬 검증을 NAS 배포 성공으로 간주하지 않는다. NAS 실측 결과는 `schedule-auto/RESUME.md`에 기록한다.
