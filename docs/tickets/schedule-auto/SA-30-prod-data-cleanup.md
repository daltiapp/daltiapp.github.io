# SA-30 · 운영 데이터 선행 정리

- 단계: 3 적용 · 선행: SA-22(G4 승인) · 크기: S
- 운영 데이터 변경이므로 변경안을 사용자에게 보여주고 승인받은 뒤 커밋한다.

## 목적

자동화를 켜기 전에 이중 등록과 장소 누락 원인을 운영 데이터에서 없앤다.

## 작업

1. **비정규 URL 6건**(2026-09-29 기준): `url`이 `https://www.agility.co.kr` 4건, `https://www.agility.co.kr/17` 2건(10/04 코리아어질리티클럽 점/어·비/노 포함). 각 대회의 실제 상세 게시물 주소를 찾아 바꾼다. 추정 주소 금지. 원문이 없으면 그대로 두고 목록에 사유를 남긴다(자동화의 퍼지 중복 검사 대상).
2. **누락 장소**: `발트바우`, `초록미소마을`을 SA-13 결과로 `venue.json`에 추가(주소·좌표 사람 확인).
3. **SA-20 보고서의 정답 오류**: 원문과 다르게 입력된 운영 값이 있으면 목록으로 보여주고 승인된 것만 수정.
4. 운영 저장소에는 현재 `review/` 디렉터리가 없다(2026-09-29 로컬 확인). 새 파이프라인 첫 실행이 만든다. 미리 만들지 않는다.

## 주의

- URL 변경은 중복 식별자 `(name, startAt, url)`를 바꾼다. 같은 커밋에서 하네스 `--scope all`을 통과해야 한다.
- 오늘 날짜가 접수 시작·마감·대회 전날인 대회를 수정하면 `schedule_send_real`(10:00) 대상에 영향이 있는지 확인한다. 날짜 필드는 이 티켓에서 바꾸지 않는다.
- manifest `dataVersion`·`forceRefreshKey`·`updatedAt`을 같은 커밋에서 올린다.
