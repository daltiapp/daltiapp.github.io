# SA-22 · 섀도 운영 (실제 사이트 → 테스트 저장소)

- 단계: 2 검증 · 선행: SA-21 · 기간: 최소 2주 · 게이트: G4

## 목적

실제 게시물로 매일 돌려 보고, 사람이 운영에 수동 입력한 결과와 비교해 운영 적용 여부를 판단한다.

## 운영 방식

- `schedule_auto_test`가 매일 실제 agility.co.kr을 확인하고 테스트 저장소에 반영한다.
- 테스트 저장소 기준선은 섀도 시작 시점의 운영 스냅샷으로 **고정**한다. 운영 수동 입력이 매일 기준선에 섞이면 같은 대회가 “이미 있음”으로 처리돼 비교할 수 없기 때문이다.
- 운영자는 기존 방식대로 운영에 수동 입력을 계속한다.
- 테스트 승인 요청에는 실제로 판단한다. 값이 맞으면 [반영], 틀리면 [보류]하고 틀린 필드를 기록한다.
- 기간: 최소 2주, 그리고 실제 신규 대회글 3건 이상을 처리할 때까지(최대 4주, 넘으면 사용자와 기간 재결정).

## 매주 기록

| 항목 | 내용 |
| --- | --- |
| 실행 | 예정 대비 성공 횟수, 실패 원인(사이트·API·코드 구분) |
| 감지 | 운영에 수동 입력된 KAU 대회 중 자동 감지한 비율, 놓친 글 |
| 정확도 | 자동 결과 vs 운영 수동 입력(idx + 날짜로 대응), 필드별 불일치, 무경고 오류 |
| 중복 | 이중 등록 후보·오탐 |
| 승인 | [반영]/[보류] 수, 보류 사유, 승인까지 걸린 시간 |
| 사용량 | Codex 호출 수(판독·장소 조회), ChatGPT 사용 한도 경고 여부 |
| 로그인 | Codex 로그인 7일 이후 유지 여부 |
| 토큰 | Drive refresh token 7일 이후 정상 여부 |

## 통과 기준 (G4)

- [ ] 핵심 필드 무경고 오류 0건, 이중 등록 0건
- [ ] 코드 원인 실패 0건(외부 장애는 경보가 정상 발송됐으면 허용)
- [ ] 운영 수동 입력 KAU 대회 중 놓친 글 0건(놓쳤다면 원인 수정 후 재확인)
- [ ] Drive 토큰 7일 이후 정상
- [ ] 최종 보고서 제출 후 **사용자 명시 승인**
