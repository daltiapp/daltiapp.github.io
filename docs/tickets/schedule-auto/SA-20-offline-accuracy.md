# SA-20 · 과거 게시물 재현 정확도 검증

- 단계: 2 검증 · 선행: SA-12, SA-13 · 크기: M · 게이트: G2

## 목적

이미 사람이 입력한 대회를 정답으로 삼아, 자동 판독 결과가 운영에 넣어도 될 수준인지 숫자로 판단한다.

## 방법

1. 입력: SA-11 fixture(원문 HTML·이미지) + `expected.json`(현재 v3 `match.json`의 같은 idx 항목).
2. 실행: 판독 → 교차검증 → 장소 해석 → 게이트 판정까지. Drive 업로드와 반영은 하지 않는다. 결과를 `tests/fixtures/schedule_auto/report/`에 저장.
3. 비교 단위: 게시물별 대회 수, 대회별 13개 필드. 이름은 공백·기호 정규화 후 비교.
4. 분류:
   - 일치
   - 불일치 + 경고 있음(사람이 잡을 수 있음)
   - **무경고 오류**: 불일치인데 경고가 없고 게이트가 통과로 판정

## 통과 기준 (G2)

| 항목 | 기준 |
| --- | --- |
| 핵심 필드(`startAt`, `endAt`, `applicationStartAt`, `applicationEndAt`, `location`) 무경고 오류 | **0건** |
| 게시물별 대회 수 불일치 | 모두 경고로 표시(무경고 0건) |
| 기존 장소 매칭 | 신규 venue 오생성 0건 |
| 기타 필드(`judge`, `matchTypes`, `eventType`, `club`, `name`, `detailNotice`) | 일치율 기록, 무경고 오류 목록을 사용자가 확인 |

- 정답 자체가 틀린 것으로 판단되면(원문과 수동 입력이 다름) 정답에서 빼고 사유를 보고서에 적는다. 운영 데이터 수정은 SA-30에서 따로 처리한다.
- 기준 미달이면 SA-12(프롬프트·교차검증) 또는 SA-13으로 돌아가 수정 후 전체 재실행한다. 기준에 맞추려고 fixture를 빼지 않는다.
