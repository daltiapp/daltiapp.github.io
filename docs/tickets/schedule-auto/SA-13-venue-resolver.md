# SA-13 · 장소 해석기 (별칭·카카오)

- 단계: 1 개발 · 선행: SA-10 · 크기: M · 설계: 5.4절

## 목적

판독한 장소를 기존 `venue.json`에 연결하고, 없으면 이름·도로명 주소·좌표를 갖춘 새 venue 초안을 만든다.

## 범위

1. **기존 매칭**: 정규화(공백·괄호·“일원” 등 제거) 후 `venue.json`의 `name` 비교 → 별칭표 `review/venue/venue_aliases.json`(앱이 읽지 않는 경로) 조회.
2. **신규 검색(카카오 로컬 REST)**:
   - 주소 원문이 있으면 `GET /v2/local/search/address.json`
   - 장소명으로 `GET /v2/local/search/keyword.json`, 주소의 시·군으로 후보를 좁힘
   - 두 결과가 모두 있으면 거리 2km 이내일 때만 확정. 후보가 여러 개이거나 멀면 `required` 경고
3. **venue 초안**: `{name, location: {name, address, latitude, longitude}, photos: []}`. 주소는 도로명 우선, 없으면 지번. 좌표는 카카오 `y`→latitude, `x`→longitude, 한국 범위(위도 33~39, 경도 124~132) 검사.
4. `미정`은 venue를 만들지 않는다.
5. 신규 venue는 게이트에서 항상 승인 대상이다. 텔레그램용 확인 링크 `https://map.kakao.com/link/map/<이름>,<위도>,<경도>`를 만든다.
6. 쿼터·오류: 401/429/5xx는 재시도 없이 경고로 남기고 반영을 막는다. 키는 `Authorization: KakaoAK <키>` 헤더로만 보내고 로그에 남기지 않는다.

## 참고

- 무료 쿼터: “키워드로 장소 검색”, “주소로 좌표 변환” 각각 일 100,000건(2026-09-29 카카오 문서 확인, 개발자 계정의 첫 번째 카카오맵 활성 앱 기준).
