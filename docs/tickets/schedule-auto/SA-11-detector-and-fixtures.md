# SA-11 · 감지기 확장 + 검증용 fixture 수집

- 단계: 1 개발 · 선행: SA-10 · 크기: M

## 목적

신규·변경 게시물의 원문(HTML·이미지·신청 페이지)을 안정적으로 확보하고, 이후 모든 검증에 쓸 고정 fixture를 만든다.

## 범위

- `schedule/schedule_detect_kau.py`의 목록 파싱·대회글 판별·제목 날짜 파싱·이미지 추출·URL 정규화를 import해 재사용한다. 기존 파일 동작은 바꾸지 않는다.
- 신규·변경 게시물만 상세 HTML, 본문 이미지(순서 유지, 최대 12장), 신청 페이지 텍스트를 캐시(`<output>/schedule_auto/cache/<idx>/`)에 저장하고 SHA-256을 기록한다.
- `kau_source_state.json` 형식의 지문으로 변경을 판단한다. 지문이 같으면 다시 받지 않는다. 첫 실행은 기준선만 기록한다.
- 목록 항목이 0건이면 “게시물 없음”이 아니라 장애로 보고한다.
- 요청 간격은 기존 `PAGE_SLEEP`(1.5초) 이상을 유지하고, 기존과 같은 User-Agent를 쓴다(`robots.txt`는 `/17` 허용).

## fixture 수집 (SA-20 정답 세트용)

- 현재 v3 `match.json`의 KAU 원문 게시물(`agility.co.kr` URL 26건 중 상세 idx가 있는 항목)을 대상으로 HTML·이미지를 1회 수집해 `tests/fixtures/schedule_auto/<idx>/`에 저장한다.
- 정답 파일 `expected.json` = 같은 idx의 현재 `match.json` 항목들. 수동 입력 오류가 의심되는 값은 정답에서 제외하고 사유를 적는다.
- 이미지 저장소 용량이 크면 테스트 fixture는 Git LFS 또는 저장소 밖 경로를 쓴다(구현 시 결정, 운영 이미지 캐시는 Git에 넣지 않는 기존 원칙 유지).

## 완료 조건

- [ ] 오프라인 fixture 테스트: 목록 0건(장애), 제외 글(세미나·결과·업데이트), 신규, 변경(지문 변경), 첫 실행 기준선
- [ ] fixture 세트와 `expected.json` 목록(게시물 수·대회 수)을 문서화
- [ ] 실제 사이트 호출은 수동 수집 명령에서만 발생하고 테스트에서는 발생하지 않음
