## 목적

NAS가 만든 대회일정 초안을 웹에서 확인·수정·승인한 뒤 JSON 생성과 GitHub 커밋·푸시를 실행한다. 수집은 NAS만 담당하며 검수 웹을 열거나 수집 중지 API를 호출해서 수집을 재개하지 않는다.

## 구현 범위

1. NAS 상태 디렉터리의 큐 v2와 배치 API 연결. 기존 Data Studio의 저장소 내부 v1 큐만으로 완료 처리하지 않는다. NAS 서버/인증/접속 방식은 구현 전 확인한다.
2. 게시물 원문·이미지와 `drafts[]` 전체 일정 필드·근거·경고를 나란히 표시.
3. 장소는 기존 등록을 연결한다. 미등록 장소가 있는 일정에서만 보조 등록 화면을 연다: 주소 입력 → 서버 지오코딩 호출 → 후보와 지도 핀 확인 → 이름·주소·좌표 수동 수정. 검색 실패는 검수로 남기고 첫 결과를 자동 선택하지 않는다.
4. Geoapify와 데이터 원천 출처·라이선스 표시. GPS를 사용하는 앱·공개 JSON 설명의 출처도 배포 작업과 함께 준비한다.
5. 저장/반려와 승인/배포 구분. 필드 수정 시 기존 승인·미리보기 무효화. 필수 경고가 남은 항목은 반영 불가.
6. 서버가 최종 JSON diff·대상 파일 SHA·하네스 결과를 만들고, 승인된 내용의 해시에 묶인 배포 요청만 받는다. 브라우저에 GitHub 자격증명/API 키 노출 금지.
7. 승인 후 allowlist JSON·manifest 단일 커밋·push. 성공 SHA와 실패·재시도 상태 표시. 같은 배치 동시 승인·재요청은 한 번만 반영.
8. 원본/활성 데이터 변경·만료 배치는 재검수. 큐·캐시·비밀값을 정적 데이터 저장소에 커밋하지 않는다.
